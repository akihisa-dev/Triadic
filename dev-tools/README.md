# 認識合わせのための開発ツール

利用者と開発者が、仕様・見え方・操作について同じものを見て確認するためのツールをここで管理します。製品の機能と配布物には含めません。

## 起動と入口

リポジトリ直下で `npm run dev:tools` を実行し、[開発ツール一覧](http://127.0.0.1:4173/dev-tools/index.html)を開きます。`npm run dev:ui` と同じ開発サーバーを使用するため、すでに起動している場合は追加起動せず、そのまま一覧を開けます。

| ツール | 確認すること | 本体・参照先 |
|---|---|---|
| [カラーデザイン確認](http://127.0.0.1:4173/dev-tools/color-design/index.html) | 仕様と確認案の色、明暗の見本、入力・選択・ダイアログ | `color-design/` |
| [実装画面の確認](http://127.0.0.1:4173/tests/ui/preview.html?data=large) | 現在の画面・操作とサンプル予算 | 自動テストと共通の `tests/ui/preview.html` を使用 |

## 保管と追加

- 新しい認識合わせ用ツールは、`dev-tools/<目的が分かる名前>/`へ本体・確認案・専用素材をまとめ、一覧とこの表へ追加します。必要になったツールから追加します。
- 製品の仕様・色・データ構造は、それぞれの正本を参照します。ツール側に別の正本や製品の処理のコピーを作りません。
- 確認案は製品と分けて保管し、何が仕様で何が案かを表示します。製品への反映は利用者の確認後に行います。
- 自動テストは `tests/ui/` に置きます。テスト用のデータやファイル操作の代替処理は既存の仕組みを共有し、ツール内へ複製しません。
- ツールの画面と候補ファイルはGitで管理します。実行時の一時状態、画像による検証記録、利用者データを本体へ混ぜません。外部送信や実ファイルへの保存を伴う操作を追加する場合は、その影響を明示します。

## 配色の確認から反映まで

1. `color-design/draft.css` に確認案を記述します。指定していない色は製品の `Triadic-extension/src/extension/styles/palette.css` を使います。
2. カラーデザイン確認を開き、仕様カラーパレットと明暗の見本を提示します。ページ内の色選択は一時的な変更で、再読み込みすると候補ファイルの状態へ戻ります。
3. 利用者が承認した色だけを製品の正本と `docs/color-palette.md` へ反映します。
4. 候補ファイルを空に戻し、仕様と見本の一致、実画面の表示・操作を確認します。

配色ページと一覧からの移動は `npx playwright test color-design.spec.ts` で通常幅・狭幅を検証します。コミット前の標準検証はリポジトリ共通の `npm run verify` です。
