# 業務スナップショットの比較

履歴を含む全体export・再取込・履歴削除・VACUUMを、正規DDLで作った付属メモリ領域へのINSERT SELECTへ置き換えました。業務テーブルとsqlite_sequenceを転記し、業務だけのbytesを専用入口で完全検査します。入力ファイルのDDLを実行せず、元の業務テーブル・履歴を変更しません。通常ファイルの完全検査は維持します。

## 再現と結果

## メモリと確認範囲

診断JSONは呼出前後のRSS・heap差、プロセス累積最大RSSを記録します。GC・WASMの再利用に影響され、同期実行中の関数単体のピークを測れません。中間コピーの実バイト数減少は確認済みですが、ピークメモリの減少率や枯渇しない件数は主張しません。実Chromeの画面停止・利用者の実ファイル保存時間も未測定です。

全業務テーブルのNULL・明示0・手修正・識別子・改訂・参照・順序・採番状態の一致と、転記失敗時の元データ保持・作業領域解放を自動確認します。従来の時点履歴と操作取消テストも、初回・5分期限・終了前記録・復元前後の保全・取消・やり直し・失敗・競合を検証します。保存形式・履歴保持・保存場所・外部送信の方針は変わりません。
