## 確認結果と限界

全条件・全反復で、DB取り込みと完全検査は変更前2回、変更後1回、実ファイルのbytes取得はどちらも1回でした。画面へ公開した計画と履歴の検査用ハッシュは前後で一致しました。軽量読込の明細省略、履歴一覧、年度・種別選択・元bytesは標準検証でも確認しています。

ファイル取得は`getFile()`、bytes取得は`arrayBuffer()`、DB取込は実SQLite接続の構築、完全検査は`assertDatabase`、計画投影は`readContents`、履歴取得は`historyFromDatabase`を観測しています。セッション公開は状態更新と購読者への通知です。Worker依頼全体はメイン画面で送信してから返信を受け取るまでであり、初期化・転送・受信側の処理も含みます。各段階は包含関係があるため合計しません。

画面表示は操作の自動化、Reactの遷移、公開結果の一致確認、描画待ちを含みます。読み込みだけの速度ではありません。入口はDOMの出現とボタンの操作可能状態を観測したもので、画素の描画完了時刻ではありません。計測記録による負荷と時間分解能の影響があり、初回は一回の観測に留まります。同じページ内で既存Workerを使い回す連続読込、最大メモリ、利用者の実ディスクからの読込は未測定です。検査が一回になったことを、読込全体が半分になったという意味には扱いません。

標準検証、画面の通常選択・続きから・ドロップ、取消・許可拒否・不正ファイル、Worker失敗後の再試行、履歴の閲覧・復元・削除・5分期限、保存と操作取消を確認しています。Codex内のブラウザでもファイルを開いて履歴一覧が表示されることを確認しました。
