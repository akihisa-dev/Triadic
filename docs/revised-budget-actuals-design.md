# 修正予算・実績管理の設計

## この文書の目的と位置づけ

上期の実績を踏まえて下期の予算を見直し、当初の確定予算と年間の着地見込みを比較できるようにする。修正予算と実績管理を一体の大規模アップデートとして検討し、この文書を仕様の検討と実装計画の土台にする。

状態は設計検討中。ヒアリングは未完了であり、製品コード・画面・保存形式の変更はまだ開始しない。以下では合意事項、現行の仕組み、未確定事項、実装計画の案を区別する。

製品方針と合意した要件の正本は[REQUIREMENTS.md](../REQUIREMENTS.md)、実装済みの機能と制限の正本は[README](../README.md)。この文書の検討結果を、合意に応じて要件へ反映し、実装した範囲だけをREADMEへ反映する。

## 合意した利用方法と仕様

| 対象 | 合意した内容 |
|---|---|
| 目的 | 上期実績を踏まえて下期を見直し、当初の確定予算と修正予算を比較する |
| 年間の着地見込み | 上期の実績そのもの＋下期の修正予算 |
| 上期の全体額 | 前年額＋施策実績の増減合計で求めた実績額を使う |
| 下期の全体額 | 現在と同じく、選んだ前年見込または前年実績の金額＋修正予算の施策の増減で計算する |
| 実績の入力 | 施策入力で前年からの増減額を入力する。部署・業種・勘定科目ごとの実績額もその集計から求め、別の実績入力は設けない |
| 施策実績の初期値 | 一次予算と同じく0から入力し、予算の変更には追従させない。増減0なら計算した実績額は前年と同額になる |
| 実績の入力候補 | 入力欄に予算額を薄く表示する。採用前の候補は保存・集計に含めない |
| 候補に使う予算 | 上期実績を入力するときは確定予算、見直し後に下期実績を入力するときは修正予算 |
| 候補の採用 | Tabで候補を実績として入力し、次のセルへ移動する |
| 修正予算の入力 | 一次予算・確定予算と同じように、施策の月別金額を入力する |
| 修正予算の未入力月 | 確定予算の有効金額を使い、確定予算の変更に追従する |
| 修正予算の入力済み月 | 入力した金額を使う。0も明示的な入力として扱う |
| 修正予算の数 | 1種類を更新して使う。見直しごとの予算種別は追加しない |
| 総原価表・展開表の予算比較 | 一次予算・確定予算・修正予算から比較する2種類を選べる。1種類だけの表示もできる。3種類同時表示は行わない |
| 当初の確定予算 | 修正予算の入力で書き換えず、比較対象として保持する |

一次予算・確定予算・修正予算・実績は、いずれも前年からの展開として扱う。例えば、ある月の前年額が100、施策実績の増減合計が8なら、その月の実績額は108になる。別の実績総額を入力して施策実績と照合する仕組みは設けない。

修正予算の年間額は、上期については前年額＋施策実績、下期については前年額＋修正予算の施策増減から求める。上期の実績額に施策実績を再び加算しない。

## 現行の仕組みとの関係

現行の施策入力は前年からの月別増減を扱い、前年の科目別金額と施策増減から予算を求める。一次予算・確定予算は同じ施策と科目行を共有する。確定予算の未入力月は一次予算の金額を使い、入力した月はその金額を使う。

修正予算はこの月別入力と未入力月の扱いを拡張する。実績も同じ施策の月別入力として扱うが、未入力月に予算額を自動適用せず、候補を採用したときに実績の入力値へ変える。

総原価表・展開表の前年表示と予算計算に使う前年の選択は、[製品方針と要件](../REQUIREMENTS.md#前年見込前年実績と基準前年)を参照し、実装計画の具体化時にコードと照合する。比較する予算は最大2種類という今回の合意を、前年列を含む表全体の列数制限へ置き換えない。

[単年度ファイルと予算種別の設計](single-year-plan-design.md)には、現行範囲から修正予算・実績を除く記述がある。本アップデートで範囲を拡張する際に関連箇所を更新する。以前の実装や制限を、そのまま今回の設計へ戻す根拠にはしない。

## 実績の入力候補

実績を入力するとき、上期は確定予算、見直し後の下期は修正予算の同じ施策・科目行・月の金額を候補にする。修正予算が確定予算の金額を使っている月も、修正予算として有効な金額を候補に使う。

候補の表示だけでは入力・保存・集計を変更しない。Tabで採用すると候補の金額を実績の入力値にし、次のセルへ移動する。採用した後は予算の変更へ自動追従させない。通常の実績入力として扱う。

未入力の施策実績は0から始めるため、通常の入力値0と候補を同じ位置でどう表示するかを設計する必要がある。候補を出す条件、明示的な0入力との区別、候補がある場合とない場合のTab、逆方向の移動、範囲選択・文字編集中の操作、読み上げでの伝え方は未確定とする。予算額を薄く表示することを、採用済みの実績額として表示することに置き換えない。

展開表では施策実績を確認できるようにする。別入力の実績総額と施策実績の不一致を扱う差額や、差を埋めるための施策を追加する必要はない。

## 続けて決める仕様

| 論点 | 必要な判断と影響 |
|---|---|
| 実績を使う月 | 今回の目的は上期実績＋下期修正予算。上期・下期に固定するか、実績を使う月を指定するかは未確定。候補に使う予算の選択とも整合させる |
| 施策実績と年間の表示 | 上期は施策実績、下期は修正予算の施策増減を表示するか、その年間合計が何を意味するかを決める |
| 当初の確定予算の保持 | 修正予算の入力による非変更は合意済み。確定予算自体を後で編集できるか、前年額・マスタ・共通の施策情報の変更が比較対象へどう影響するかは未確定。凍結や複製保存を独自に追加しない |
| 比較と差額 | 最大2種類という選択範囲は合意済み。差額をどちらから引くか、実績単独の表示・比較も可能にするか、選択状態の保存と初期表示は未確定 |
| 入力と編集 | 施策入力での実績・修正予算の切り替え、候補を出す条件と表示、Tab以外の操作、編集可能月、未入力へ戻す操作を決める |
| 既存画面への適用 | 総原価表・展開表・施策一覧・施策詳細・内訳に加え、ダッシュボード・検索・複製・開始年月などへの適用範囲を照合する |
| 保存・取消・履歴 | 施策実績・修正予算・対象月・選択状態の保存構造と更新単位を決める。取消、履歴閲覧、差分、復元、複数ウィンドウの同期でも同じ値と関係を保つ |
| Excel入出力 | 出力・計算元・入力フォーマット・取り込み確認で、修正予算と施策実績をどう扱うかを決める |
| サンプルと説明 | 既存サンプルの上期実績・施策実績・下期見直しをどう設計するかを決め、画面とデータ・計算の仕組み・処理の流れへ反映する |

別の実績入力や、実績額に施策実績を重ねて加算する計算は設けない。施策の「中止」という新しい状態、修正予算専用の開始・取消操作や上期の編集禁止は、今回の合意に含まれない。

## 実装計画の案

以下は作業の依存関係を示す計画案であり、実装開始や各仕様への承認ではない。合意した前年からの展開を共通計算へ適用し、対象月・入力候補・保存構造を設計した上で画面と入出力を具体化する。

| 順序 | 作業 | 次へ進む条件 |
|---|---|---|
| 1 | 合意した実績・修正予算の計算に対し、対象月、入力候補、当初確定予算の保持範囲を決定 | 上期・下期・年間と実績入力の操作を説明できる |
| 2 | 保存・更新・同期・取消・履歴の設計と、影響する処理の調査 | 0・未入力・未修正の区別、失敗時の保護、比較対象の保持を定義できる |
| 3 | 画面と操作、表の合計・内訳・比較の設計 | 対象画面・要素・変更内容を具体化し、通常メッセージで利用者の確認を得る |
| 4 | 保存処理と共通計算、関連する自動テストの実装 | 各表が同じ保存値と計算を使い、上期実績に施策を二重加算しない |
| 5 | 承認済み画面、Excel、履歴比較、関連機能への適用 | 影響範囲ごとに表示・編集・保存・再読込の結果が一致する |
| 6 | 要件・実装済み説明・対応図・サンプルの更新と全体検証 | 文書と実装が一致し、必要な検証を完了する |

実装単位とコミットの分割は、仕様確定後の影響調査から具体化する。保存形式の具体的な番号や製品のバージョン番号はこの段階では決めない。過去の保存形式との互換対応は、明示された対象範囲がない限り追加しない。

## 実装時に確認する条件

- 修正予算の未入力月は確定予算の有効金額を使い、入力済みの0や同額の入力を未入力と混同しない。
- 一次・確定・修正の金額を区別し、修正予算の入力で当初の確定予算を変更しない。
- 実績は前年額＋施策実績、下期の修正予算は前年額＋修正予算の施策増減とし、年間の着地見込みは上期実績と下期の修正予算の合計になる。
- 施策実績は0から入力し、候補を表示するだけでは金額・保存・集計を変更しない。Tabで採用した金額を入力し次のセルへ移動する。採用後は予算変更に追従させない。
- 実績額と施策実績の集計に同じ規則を使い、総原価表・展開表・施策一覧で値と内訳が一致する。
- 円単位の精度、負数、0、未入力、集計範囲超過、絞り込み時の合計、利益率を関連する計算に照らして確認する。
- 保存失敗・取消・競合・再読込・履歴復元で、金額と対象月の対応を失わない。
- 標準検証は`npm run verify`。画面変更時はCodex内ブラウザで該当表示と操作を確認し、Excelの関連変更時は`npm run test:excel`と`npm run test:ui:excel`を実行する。
- サンプル予算設計・生成元・機能対応表・対応図と説明を実装に合わせて更新する。詳細は[AGENTS.md](../AGENTS.md)に従う。

これらは今後の実装の確認条件であり、この文書の作成時に製品機能を実装・検証したという意味ではない。
