# 修正予算・見通し・実績管理の設計

## 目的と状態

前年の金額から施策の増減を積み上げ、一次予算・確定予算・修正予算・見通し・実績を同じ施策入力で扱う。上期実績を踏まえた下期の見直しと、当初の確定予算との比較を可能にする。見通し・実績も入力した施策から求め、別の公式数値との自動照合は行わない。

状態は設計検討中。ヒアリングは未完了で、製品コード・画面・保存形式の変更は未着手。本書の「合意事項」は会話で決めた仕様、「計算条件」は合意した計算を成立させる条件、「未確定事項」は追加判断が必要な箇所、「実装計画案」は着手前の案を示す。

製品方針・合意した要件は[REQUIREMENTS.md](../REQUIREMENTS.md)、実装済み範囲は[README](../README.md)、現行保存構造は[DATA_MODEL.md](../DATA_MODEL.md)を参照する。本書は大規模アップデートの設計であり、記載を実装済みと扱わない。

## 合意事項：展開と種別

「前年」は展開名として追加する。種別として「前年見込」「前年実績」を追加せず、展開「前年」の見通し・実績を使う。「実績見込」の名称は「見通し」にする。

| 施策 | 金額の意味 | 表示する種別タブ | 金額の編集 |
|---|---|---|---|
| 展開「前年」の施策 | 前年度の月別金額そのもの | 見通し・実績 | 手入力できる |
| それ以外の通常の施策 | 当年度の前年からの月別増減額 | 一次・確定・修正・見通し・実績 | 各種別の規則に従って入力する |

施策の構造は共通にする。「前年」では一次・確定・修正のタブを非表示にする。表示しない種別の保存値・計算上の扱いは未確定だが、隠した値が意図せず加算される設計にはしない。

## 合意事項：前年の用意と年度の引き継ぎ

- 前年専用の入力画面に依存せず、展開「前年」の施策へ金額を入力する。
- 前年の見通し・実績は独立して保持する。前年が確定していない時点でも見通しを使って予算を作れる。確定後も見通しを残す。
- 各予算で、展開「前年」の見通し・実績のどちらを前年額として使うか選ぶ。前年実績を入力しただけで、作成済み予算の選択を自動で切り替えない。
- 初年度には引き継ぎ元がないため、展開「前年」の施策へ直接入力する。
- 施策は必要な業種・部署の単位で分けられる。まとめて始めるなら、1業種・1部署の1施策に全科目を入力してもよい。すべての業種・部署の組み合わせを用意することを前提にしない。
- 前年を1業種・1部署へまとめた場合、その金額は選んだ分類に属する。入力していない分類別内訳をアプリが推測して作ることはない。
- 翌年度には前年度の施策実績を引き継ぐ方針とする。どの施策をどの前年施策にするか、金額・分類・科目・年度をどう引き継ぐかは未確定。

展開「前年」の施策合計が、そのまま予算・見通し・実績の計算に使う前年額になる。

## 今回の対象外

「答え」と呼んでいた公式数値の入力、施策の見通し・実績との自動照合、残差の自動計算とそれを受け持つデフォルト施策は、今回のアップデートの対象から外す。公式数値との不一致を理由に入力や保存を止める仕組みも設けない。

部署・業種別の公式数値を用意する作業をアプリの利用条件にしない。施策の分類や金額が公式数値と一致することを、自動で保証する機能は持たない。

## 計算条件：前年からの展開

金額は円単位で計算し、表示用の丸め値を計算元へ戻さない。同じ月・勘定科目・集計対象の業種・部署について、次の関係で求める。

| 記号 | 意味 |
|---|---|
| P | 展開「前年」の施策合計。計算に使う見通し・実績の選択に対応する前年額 |
| S種別 | 展開「前年」を除く施策について、選んだ種別の月別増減を合計した金額 |
| T種別 | その種別の当年度の合計額 |

一次・確定・見通し・実績の基本式は、T種別＝P＋S種別とする。修正も同じ式を使い、上期実績を使う月は後述の規則で実績額を参照する。展開「前年」の金額はPにだけ含め、Sへもう一度含めない。

| 前年額P | 施策の増減合計S | 当年度の合計T |
|---:|---:|---:|
| 100 | 0 | 100 |
| 100 | 10 | 110 |
| 100 | −5 | 95 |

施策金額の引き継ぎと、計算に使う前年の選択は別の条件とする。上期に確定予算、下期に修正予算の施策金額を使っても、前年の選択までそれらの予算に自動で揃えない。見通し・実績の前年選択の初期値・保存先などは未確定。表示する前年と計算に使う前年を混同しない。

公式数値を別に入力してTを自動調整することはしない。施策の金額を変更したら、その変更を合計へ反映する。絞り込み後の合計の表示規則は各表について別途決める。計算範囲超過で正しく計算できない値を、上限へ切り詰めて正常な合計に見せない。

## 合意事項：施策金額の引き継ぎと入力

見通しは、その時点で予想する結果を入力する種別とする。修正予算を作るためだけの金額ではない。見通しと実績は、それぞれ入力した値を独立して持つ。

一次予算と確定予算の現在の関係と同様に、未修正の月は指定された予算の施策金額を使い、予算変更に追従する。一度だけ初期値をコピーする動作ではない。

| 種別 | 未修正月に使う施策金額 | 入力した月 |
|---|---|---|
| 修正予算 | 確定予算 | 修正予算に入力した値 |
| 見通し・上期 | 確定予算 | 見通しに入力した値 |
| 見通し・下期 | 修正予算 | 見通しに入力した値 |
| 実績・上期 | 確定予算 | 実績に入力した値 |
| 実績・下期 | 修正予算 | 実績に入力した値 |

修正予算は1種類を更新して使う。修正予算の未修正月も確定予算へ追従するため、上期中でも、下期の見通し・実績は修正予算の変更がなければ確定予算と同じ施策金額になる。修正予算を変更した下期の月は、未修正の見通し・実績にも反映する。

見通し・実績に入力した月は、0や予算と同額の入力であってもその入力値を保持し、予算の変更には追従させない。一方だけを入力して、他方の明示入力を上書きしない。見通し・実績・修正への入力で確定予算を書き換えない。

この表の引き継ぎ対象は施策の月別増減額。前年の見通し・実績の選択や、前年を足した合計額をコピーする規則ではない。前年の選択が異なれば、施策の増減額が同じでも当年度の合計額は異なる。

展開「前年」の見通し・実績は前年度の金額そのものなので、この当年度の施策増減の引き継ぎ表は適用しない。前年施策は見通し・実績だけを表示して入力する。

見通し・実績を0から入力し、薄い予算候補をTabで採用する方式は使わない。未修正月には実際の有効金額として予算の施策金額を使い、表示・集計に含める。Tabへの候補採用機能は追加しない。

未修正へ戻す具体的な操作、未修正と明示入力の表示、保存・取消・履歴での記録方法は未確定。未修正・明示0・同額の明示入力は区別できる必要がある。

## 合意事項：比較と年間の着地見込み

修正予算の年間額は上期実績＋下期の修正予算とする。上期は前年額＋施策実績で求めた実績額を使い、そこに施策実績を再度加えない。下期は選んだ前年額＋修正予算の施策増減で求める。

入力した修正予算の施策増減と、上期実績を含む年間表示の合計額は区別する。上期・下期の境界を固定するか、実績を使う月を指定するか、上期・下期ごとの施策金額の引き継ぎとどう対応させるかは未確定。

総原価表・展開表は、一次・確定・修正から比較する2種類を選び、1種類だけの表示も可能とする。3種類同時表示は行わない。見通し・実績を比較対象へ加える案は未回答。最大2種類という合意を、前年表示や差額を含む表全体の列数制限に置き換えない。

「前年」の施策を各表のどこに表示するか、年間の施策行に上期実績と下期修正をどう合わせるか、差額の符号・既定値・条件の保存は未確定。総原価表と展開表の現行の異なる列構成を、共通部品化だけを理由に統一しない。

## 保存と更新の設計条件

以下は実装を成立させるための設計条件であり、保存テーブル・列・形式番号を確定するものではない。

- 施策・分類・科目行・月・種別の対応と、前年度の金額そのもの・当年度の増減額の違いを識別できるようにする。
- 通常の施策の見通し・実績と、前年施策の見通し・実績を取り違えず保持する。独立した金額の一方を、他方の入力で自動上書きしない。
- 修正予算の未修正月は確定予算、見通し・実績の未修正月は上期の確定予算または下期の修正予算から求める。引き継ぎ額を独立した保存値として同時に正本にしない。前年の選択をこの処理で変更しない。
- 展開「前年」の判定をユーザーが編集する名称の文字列だけに依存させず、役割と参照の保存方法を決める。
- 前年額・施策金額・分類を更新した場合、各表を同じデータから再計算する。保存失敗・取消・競合・履歴閲覧・復元でも別時点の値を混ぜない。
- 削除・科目変更・所属変更・展開「前年」と他の展開との変更が、保存済み金額や当初の確定予算をどう扱うかを決める。画面でタブを隠すだけをデータ保護の実装とみなさない。

実装の保存形式・精度・参照検証は[月別金額と保存構造](../DATA_MODEL.md)、履歴の現行設計は[履歴の設計](data-history-design.md)を調査する。旧形式との互換対応は明示された範囲がない限り追加しない。

## 未確定事項と確認順序

| 順序 | 論点 | 判断による違い |
|---|---|---|
| 1 | 見通し・実績で使う前年の選択 | 合計の計算元、選択の初期値・保存先を決める |
| 2 | 未修正と明示入力の扱い | 0・同額の明示入力の保持、未修正へ戻す操作、表示・保存・取消・履歴を決める |
| 3 | 実績を使う月・見直しの状態 | 年間の合計、施策金額の確定／修正からの引き継ぎ、月次の更新範囲を決める |
| 4 | 見通し・実績を含む比較と表示 | 比較対象、差額、前年施策の配置、絞り込み・集計を決める |
| 5 | 展開「前年」とマスタの編集 | 役割の識別、分類、科目行、展開変更、削除・複製、非表示種別の扱いを決める |
| 6 | 年度の引き継ぎ | 前年度の施策実績から、翌年度の前年額と内訳をどう作るかを決める。前年額と増減額の違いを保つ |
| 7 | 共通情報と当初の確定予算の保持 | 元となる前年・分類・科目を編集しても比較対象をどう保つかを決める。凍結や全マスタの複製保存は未合意 |

部署に複数業種がある場合があり、部署から業種を一意に推定しない。元資料の分類情報を前提とする一括取り込みや、施策の「中止」という状態は合意した機能に含めない。

## 実装計画案と検証

| 段階 | 作業 | 完了条件 |
|---|---|---|
| 1 | 前年・各種別の計算と入力、未確定事項を決定 | 科目・月・分類単位の金額例で説明できる |
| 2 | 施策の識別、保存・計算・更新・年度引き継ぎの設計 | 元の保存値から各種別の合計を再現でき、未入力・0・明示入力を混同しない |
| 3 | 施策入力、各表・比較・未修正と明示入力の画面案 | 金額の意味、編集可能な範囲、元の操作との関係を具体化する |
| 4 | 共通計算と保存処理、自動テストの実装 | 前年の二重加算がなく、見通し・実績も入力した施策から求められる |
| 5 | 画面、同期・取消・履歴・復元、検索・複製・ダッシュボード、Excelへの適用 | 各入口で同じ元データ・種別・分類・月を参照し、保存失敗でも入力を失わない |
| 6 | 要件・README・対応図・説明・サンプルの更新と全体検証 | 実装済み範囲が説明と一致し、必要な確認が完了する |

現在の前年入力、固定種別、基準前年選択、前年額の保存、科目行の共通編集、Excelの前年入力形式を調査し、関連する廃止・置き換えを具体化する。[単年度ファイルと予算種別の設計](single-year-plan-design.md)の現行範囲を、今回の拡張を制限する根拠にしない。実装済みの文書は実装時に更新し、検討段階で未実装の操作手順へ置き換えない。

実装時は、前年施策の見通し・実績の独立、選択した前年と計算元の一致、前年と当年度の増減の二重計上防止、正負と0・入力変更への追従、非表示種別と展開変更時のデータ保護、上期・下期の予算への追従と明示入力の保持、同一の数値での保存・取消・履歴復元を自動テストで確認する。金額は丸める前の値で一致を検証する。

標準検証は`npm run verify`。画面変更はCodex内ブラウザで確認し、総原価表・展開表の変更は`npm run test:table-contracts`と実ブラウザで検証する。Excel関連変更では`npm run test:excel`と`npm run test:ui:excel`を実行する。サンプル予算設計・生成元・対応表・対応図・計算と処理の説明を関連実装と照合する。詳細は[AGENTS.md](../AGENTS.md)に従う。

本書は設計検討中であり、実装・実環境検証・ヒアリングの完了を意味しない。
