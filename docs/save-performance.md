500施策では約5〜7%短縮しました。小・中量では範囲が重なる条件があり、一律の速度改善とは評価しません。残る検査の削減は安全性への影響が大きく、今回の測定だけを根拠には実施しません。

## 確認範囲と制限

ファイル境界は専用のNode一時ファイルへの読み書き・renameで代替しています。Chromeの実ファイル保存、許可取得、端末ストレージの差、画面の体感時間は測定していません。合成データの件数は製品全体の性能保証ではありません。一時ファイル・ビルドは終了時に削除し、利用者のファイルには触れません。

共通読み取りのテストは、従来のデータ・履歴の読取結果との一致、元データ保持、破損・旧形式・不正値・不正参照・不正履歴状態・履歴内部用データの拒否を確認します。標準検証では保存失敗・競合・再試行・操作取消・時点履歴復元・参照専用操作の保護も確認します。

## Issue #73：通常保存の比較対象を限定

通常の更新処理を専用接続へ一度だけ適用し、対象施策の本体・行・手修正、前年分類、関係するマスタ・所属・順序だけをSQLite内で前後比較します。比較用の一時表は保存前に除去します。書込件数だけで判断せず、改訂番号だけの差は除外し、明示0・同額手修正・継承復帰・NULL・順序を保存項目として区別します。無変更は更新をロールバックし元bytesそのものを返します。変更前は元bytes、変更後は更新接続から取消用状態を作ります。

比較だけのデータ全体の復元は1→0回、画面側の全体JSON化は2→0回です。変更時のデータ投影は比較と保存結果の2→1回、無変更は1→0回。必要な保存結果の投影・各完全検査・外部照合を維持します。データの完全検査回数は初回変更9→7、履歴あり8→6、同値3→1。これは同一接続の再利用と中間読込・exportをなくした結果であり、検査条件を緩めたものではありません。取消用状態の作成は実変更2回・同値0回のままです。
