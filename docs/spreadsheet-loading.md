# 入出力画面の読み込み測定

入出力画面を初めて選択したときにExcel処理を読み込みます。画面の切り替えアニメーション中に読み込みを開始し、待機中も別の画面へ移動できます。読み込み失敗時は保存済みの計画を保持し、画面の再読み込みから再開できます。

## 再現手順

`npm run build` と `npm run dev:ui` を実行した後、別の端末で `node scripts/measure-spreadsheet-loading.mjs /tmp/spreadsheet-loading.json` を実行します。インストール済みChromeと全機能確認用サンプルを使い、毎回新しいブラウザ環境で5回測定します。利用者の実ファイルは操作しません。

画面に表示されるボタン・見出しを待つ時間を測るため、画面の切り替え時間や操作自動化の待機も含みます。端末・ブラウザ・キャッシュ状態によって結果は変わります。ファイルを開いてからHomeに到達する時間はSQLiteの読み取りも含み、Excel分割だけの指標ではありません。

## 同じ環境での比較

2026-10-11、macOS arm64、Apple M6、Node 26.4.0、同じインストール済みChrome、1280×864、日本語設定。変更前はe147462、変更後は今回の入出力画面分割です。並行してビルド・検証を実行せず測定しました。時間は5回の中央値、括弧内は最小〜最大、単位はmsです。

| 対象 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 最初の「ファイルを開く」表示 | 285.3 (271.2〜293.8) | 130.4 (127.9〜200.2) |
| ファイルを開いてHome表示 | 852.6 (845.6〜860.2) | 857.2 (846.7〜867.1) |
| 初めて入出力を選択して操作可能になるまで | 310.0 (307.4〜316.1) | 253.0 (215.0〜323.6) |

初期JavaScriptは1,819,980バイトから約716,000バイトへ減少しました。Excel処理の1,094,131バイトは入出力画面を選択するまで取得されません。5回ともブラウザの実行エラーはありませんでした。初回入出力には追加取得が必要なため、低速な環境でも同じ時間短縮が得られる保証はありません。

`tests/lazy-spreadsheets.test.mjs` は初期の依存関係にExcel関連パッケージが含まれないことを確認します。`tests/ui/lazy-spreadsheets.spec.ts` は取得前・待機中の画面移動・取得失敗・再読み込みからの復帰を確認します。
