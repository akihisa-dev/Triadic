# Triadic 次期大型アップデート全体設計

## 1. この文書の役割と完成状態

本書は、前年を施策として扱う変更、一次予算・確定予算・修正予算・見通し・実績への拡張、年度の引き継ぎ、および既存機能への適用を一体として整理する次期大型アップデートの設計書である。修正予算だけの機能設計ではない。

本書だけで目的、現行との違い、利用の流れ、金額の意味、入力と計算、保存と復元、画面ごとの差、年度の引き継ぎ、変更対象、実装順序、確認すべき条件を把握できる構成にする。末尾のソース参照は根拠と実装時の入口であり、本文を理解するための別文書の通読を前提としない。

**状態は設計検討中。ヒアリング・設計承認・製品実装・実環境検証は未完了。** 説明範囲を網羅することと、未回答の仕様を確定することを区別する。本書を詳しくするために、未合意の動作を既定の仕様へ置き換えない。

## 2. アップデートの目的、範囲、対象外

### 2.1 実現すること

1. 前年も当年度も、施策を入力する流れで扱う。
2. 前年の結果が確定する前に予算作成を始め、確定後も見通しと実績を区別して残す。
3. 一次予算、確定予算、修正予算、その時点の見通し、実際の結果を同じ施策で扱う。
4. 上期実績を踏まえて下期を見直し、当初の確定予算と年間の着地見込みを比較する。
5. 未修正月には予算の施策金額を使い、同じ値を何度も入力する負担を減らす。
6. 年度が変わったときに前年度の施策実績を前年へ引き継げるようにする。
7. 総原価表・展開表・施策一覧・関連画面・Excel・履歴が、同じ入力と計算に基づく状態を保つ。

### 2.2 対象となる変更

| 領域 | 変更の範囲 |
|---|---|
| 業務の扱い | 前年専用入力から展開「前年」の施策へ変更。種別を5種類へ拡張 |
| 入力 | 施策の役割別タブ、月別金額、未修正と明示入力、分類・科目の共通編集 |
| 計算 | 前年集計、種別別有効額、上期／下期の引き継ぎ、修正予算の年間表示、比較 |
| 画面 | 施策入力・詳細・一覧、総原価表、展開表、内訳、選択欄、関連する検索・複製・ダッシュボード |
| 保存 | 種別・前年の役割・金額・選択条件、読み込み検証、更新・同時編集 |
| 利用の継続 | 自動保存、操作取消、時点履歴、過去閲覧・比較・復元、年度の引き継ぎ |
| 入出力 | 既存3表のExcel出力と計算元、現在の前年入力フォーマットの置き換え判断 |
| 保守・配布 | 説明・対応図・サンプル・テスト・生成物・配布物の整合 |

対象に含めることは、すべての機能を無条件で増やすことを意味しない。各領域で維持・変更・廃止・未決定を整理する。

### 2.3 今回は設けないもの

- 「答え」と呼んでいた、公式の見通し・実績を別に入力する画面。
- 公式数値と施策の集計を自動照合する仕組み。
- 残差の自動計算、および展開「物量増減」・備考「残差分」のデフォルト施策。
- 公式数値との一致を、入力完了・保存・翌年度への引き継ぎの条件とする仕組み。
- 全部署×全業種の組み合わせを利用者が用意することを前提とする入力。
- 薄い予算候補を表示し、Tabで採用する機能。現在の合意は予算額への自動追従である。
- 独立した「前年見込」「前年実績」という当年度の種別。展開「前年」の見通し・実績で表現する。
- 施策の「中止」という新しい状態や、合意のない開始・取消の専用操作。
- 明示依頼のない旧保存形式との互換用移行・旧仕様の保持・旧APIの維持。
- 外部サービス、クラウド保存、外部送信、追加の拡張権限。今回の要件に必要性は確認されていない。

公式数値や分類の正しさをアプリが自動保証する設計ではない。利用者が公式資料を参照することや、施策へ金額を入力することを禁止するものでもない。

## 3. 全体の考え方と用語

### 3.1 変えない考え方

Triadicは、施策を考え、勘定科目ごと・月ごとに前年からの増減を入力し、それを積み上げて金額を求める。見通し・実績も前年からの展開として扱う。実績だけを別方式の金額として解釈しない。

一つのファイルで一つの基準年度を管理する現行構成を出発点とする。複数年度を同じファイルへ保存する拡張は合意していない。年度の引き継ぎは、まず別年度のファイルを作る処理として設計する案とし、具体的な操作はD07で決める。

### 3.2 用語の定義

| 用語 | 本書での意味 |
|---|---|
| 基準年度Y | 現在のファイルが扱う当年度 |
| 前年 | 基準年度の一つ前の年度Y−1。施策の展開名としても使う |
| 展開 | 施策を分類する既存のマスタ。「前年」を追加する |
| 種別 | 同じ施策の金額を入力・確認する切り口。一次・確定・修正・見通し・実績 |
| 前年施策 | 本文の説明上、展開「前年」を選んだ施策を指す。新しい画面名ではない |
| 当年度の施策 | 展開「前年」以外の施策。入力値は前年からの増減額 |
| 前年額 | 展開「前年」の見通しまたは実績を集計した金額そのもの |
| 施策金額 | 個々の科目行・種別・月の値。前年施策なら前年額の成分、それ以外なら増減額 |
| 合計額 | 前年額に当年度の施策増減を加えた金額。施策金額とは区別する |
| 未修正 | 対象月にその種別の独立した入力値を持たず、指定された予算額を使う状態 |
| 明示入力 | その種別・月へ金額を入力した状態。0や引き継ぎ元と同額も含む |
| 有効金額 | 明示入力の有無と引き継ぎ規則を適用して、その場で使う施策金額 |
| 参照する前年 | 合計計算に展開「前年」の見通し・実績のどちらを使うかという条件 |
| 表示する前年 | 表の比較対象として表示する前年。計算に使う前年と別条件になり得る |

「未修正」は未保存・保存失敗・入力中の不正値を意味しない。保存済みの正規の状態として成立する。

### 3.3 種別の役割

| 種別 | 利用者が扱う内容 | 他の種別との関係 |
|---|---|---|
| 一次予算 | 予算作成の最初の施策金額 | 現行の入力を出発点とする |
| 確定予算 | 確定した計画の施策金額 | 未修正月は一次予算を使う現行規則を維持する |
| 修正予算 | 見直した計画の施策金額 | 未修正月は確定予算を使う。1種類を更新する |
| 見通し | その時点で予想する結果の施策増減 | 修正予算のためだけの準備値ではない。実績と別に入力する |
| 実績 | 実際の結果として入力する施策増減 | 未修正月には予算額を使い、入力した月は入力値を使う |

実績の有効額には、明示入力していない月の予算額が含まれ得る。画面に「実績」と表示しただけで、全月を決算確定値として入力済みと判定しない。これに対する特別な確定フラグや承認操作は合意していない。

## 4. 現行構成と次期構成の違い

### 4.1 静的確認できた現行構成

| 項目 | 現行確認 | 次期の方向 |
|---|---|---|
| 保存形式 | SQLite形式33。旧形式・未知の形式を拒否 | 形式変更は必要になるが番号は未定 |
| 予算種別 | 1＝一次、2＝確定の2種類 | 5種別へ拡張。追加IDは未定 |
| 一次の保存 | 科目行ごと12か月の直接値 | 現行の意味を保つ |
| 確定の保存 | 明示入力した月だけ保存。不在月は一次を使う | 他の下流種別も同様の状態を表現する |
| 前年 | `previous_amounts` に前年見込・前年実績を別保存 | 展開「前年」の施策に見通し・実績として持たせる |
| 分類 | 保存済み施策は展開・部署・業種が必須 | 任意の細かさで施策を分ける。必須性を変える合意はない |
| 部署と業種 | 部署ごとに複数業種の所属を持てる | 一部署一業種と推定しない |
| 施策名・科目行 | 分類・名称・科目行は種別間で共通 | 共通編集の影響範囲を5種別で確認する |
| 年度 | ファイルの年度は作成後変更不可 | 年度引き継ぎは別処理として設計する |
| 比較選択 | 現行は最大2予算。表示用前年と計算用前年を別保存 | 上限2を保ち、対象拡張はD01で確認する |
| 開始年月 | 種別別の有効月額から導出、保存しない | 新しい種別と前年施策への適用を決める |

### 4.2 一律置換で済まない箇所

`kindIds` に数値を追加するだけでは成立しない。現行は次の各層に2種別前提がある。

- 型と初期値、金額解決、入力検証。
- `kind_id IN (1,2)` という保存制約と、種別2へ固定した読み込み。
- `previous_amounts` とその更新・参照保護・インデックス。
- 比較条件の一次用・確定用の固定列。
- 確定−一次に固定した比較順・比較列。
- 複製・差分・履歴・同期が扱う金額と状態。
- Excelの計算元、入力フォーマット、用途識別。
- 画面とデータ、計算の仕組み、処理の流れの説明。

次期設計では、金額を求める共通処理、施策の役割、表示・計算用の前年条件を明示的に分ける。

### 4.3 既存説明との食い違いの扱い

現在の `DATA_MODEL.md` には、科目変更・行削除を全額0に限定する記述がある。一方、確認した `applyInitiativeUpdate` は科目・行を更新し、現在の要件には金額の有無で制限しない規則がある。この不一致を次期仕様の根拠にしない。実装開始前に現行の期待動作と説明を照合し、本書のD09で5種別への影響を決める。

設計文書を詳しくする作業だけで、現行製品・保存形式・既存利用ガイドの挙動を変更しない。

## 6. 利用の流れ

### 6.1 初年度に前年を用意する

1. 基準年度Yのファイルを作る。
2. 施策入力で展開「前年」を選ぶ。
3. 必要な業種・部署を選び、科目行と12か月の金額を入力する。
4. 前年が未確定なら見通しへ、確定した金額は実績へ入力する。両方を持てる。
5. 利用者が必要とする細かさで施策を分ける。初めから全分類へ分ける必要はない。
6. 保存された前年施策の合計を、当年度の各種別の計算に使う。

この見通し・実績は前年度Y−1の金額である。当年度の通常施策の見通し・実績と年度・金額の意味を取り違えない。

### 6.2 一次から確定へ進む

1. 前年に対する施策の増減を一次予算へ入力する。
2. 確定予算は未修正月に一次の金額を使う。
3. 確定側へ入力した月だけ独立した値になる。
4. 各予算に使う前年の見通し・実績を選ぶ。前年の選択が変われば合計も変わる。
5. 確定を明示的に凍結する操作は未合意。通常の金額入力と、比較対象の保持範囲はD10で区別する。

### 6.3 見通しを更新する

1. 同じ施策の見通しを開く。
2. 未修正月には上期は確定、下期は修正の施策金額が表示され、集計にも含まれる。
3. 予想が変わった月へ金額を入力する。
4. その月は明示入力として保持し、元の予算が変わっても見通しの入力値は変えない。
5. 実績側の明示入力は変更しない。

見通しを使うために修正予算の作成完了を要求しない。修正未修正なら確定をたどれるため、上期中から下期の見通しも扱える。

### 6.4 実績を入力する

1. 同じ施策の実績を開く。
2. 未修正月は見通しと同じ参照規則で予算の施策金額を使う。
3. 実際の増減額を入力した月は独立して保持する。
4. 施策実績の合計に選択した前年額を加えて、当年度の実績額を求める。
5. 別の公式総原価表を入力する操作や、自動的な差額合わせは行わない。

### 6.5 下期を見直す

1. 修正予算の未修正月は確定予算と同じ施策金額になる。
2. 見直す月へ修正値を入力する。
3. 下期の見通し・実績が未修正なら、その修正値へ追従する。
4. 見通し・実績が明示入力済みなら、修正値へ置き換えない。
5. 年間の着地は上期実績と下期修正から確認し、当初の確定予算と比較する。

### 6.6 翌年度へ進む

前年度の施策実績を前年額へ引き継ぐ。ただし、前年度の施策実績は増減額であり、それだけをコピーしても前年度の金額そのものにはならない。前年度の前年額を含めて翌年度の前年合計が一致するよう設計する。処理の詳細は14章とD07で扱う。

## 7. 施策の役割、分類、マスタ

### 7.1 役割別の入力範囲

| 項目 | 展開「前年」 | 当年度の通常施策 |
|---|---|---|
| 入力値 | 前年度の科目別月額そのもの | 前年に対する増減額 |
| 表示タブ | 見通し・実績 | 一次・確定・修正・見通し・実績 |
| 一次・確定・修正のタブ | 非表示 | 表示 |
| 当年度予算への追従 | 適用しない | 未修正月に適用 |
| 役割 | 前年額の構成要素 | 当年度増減の構成要素 |
| 公式数値との照合 | なし | なし |
| 自動作成される差額施策 | なし | なし |

タブを隠しただけで、残っていた金額を無視できたと扱わない。保存・読み込み・計算も役割に対応させる。

### 7.2 入力単位

- 施策は一つの部署・業種を持ち、複数の科目行を持つ現行構成を出発点とする。
- 一つの科目を複数行に分ける既存の入力も扱う。科目別集計では同じ科目の行を合算する。
- 一つの施策へ異なる部署・業種を行ごとに持たせる変更は未合意。
- まとめた前年を一つの分類に入れれば、その金額の分類別集計もそこへ集まる。自動配分しない。
- 部署が所属する業種の候補と参照の保護を維持し、存在しない分類や無関係な所属を保存しない。

### 7.3 展開「前年」の識別

合意されているのは展開名と業務上の役割。文字列比較だけで役割を判定すると、改名で計算対象が変わり、同名再登録で別の展開を誤認するおそれがある。

**設計案：** 展開の保存定義に通常／前年を区別する役割を持たせ、施策は選んだ展開から役割を決める。画面表示名と内部の役割を分ける。具体的な列名・値・制約はD08で決める。

次は未決定。

- 前年役割の展開を一つに限定するか。
- 役割を利用者が変更できるか。
- 展開名・コード・並び順の初期値と変更範囲。
- 前年展開へ展開区分・期間を設定できるか。
- 前年展開を削除できる条件。
- 施策の展開を通常から前年へ、前年から通常へ変える場合の金額の扱い。

既存の通常施策を「前年」に切り替えて金額が消える動作や、非表示種別へ金額が残って後から復活する動作を無断で導入しない。

### 7.4 共通項目の編集

施策名・備考・展開・部署・業種・展開区分・期間・科目行は現行では種別間で共通。科目行の追加・削除・科目変更・分類変更は複数種別の金額へ影響する。

次期でも共通構造を保つが、単に「修正予算だけを編集した」と説明できない操作がある。金額の種別別編集と、共通構造の変更は区別し、D09・D10で保存・画面・確認方法を決める。修正予算の入力だけで当初確定予算が変わらないことと、共通科目の削除でも当初額を永久に保つことは同一の合意ではない。

## 8. 金額状態と引き継ぎの厳密な規則

### 8.1 入力値と有効額

本章の記号は科目行r、月m、種別kを対象とする。

- `M(r,k,m)`：その種別・月に明示入力した円整数。
- `M` がないこと：未修正。0という数値とは別。
- `E(r,k,m)`：入力と参照規則を適用した有効金額。
- `H(m)`：上期に属する月かを表す条件。具体的な月範囲と変更可否はD04。

金額は空の文字列・入力途中の式・不正な文字列のまま保存しない。不正入力は入力欄へ保持し、保存済みの有効額と区別する現行の保護を維持する。

### 8.2 当年度の施策の解決表

| 種別 | 明示入力がある場合 | 明示入力がない場合 |
|---|---|---|
| 一次 | 一次の入力値 | 現行の初期値0を出発点とする |
| 確定 | 確定の入力値 | `E(一次)` |
| 修正 | 修正の入力値 | `E(確定)` |
| 見通し・上期 | 見通しの入力値 | `E(確定)` |
| 見通し・下期 | 見通しの入力値 | `E(修正)` |
| 実績・上期 | 実績の入力値 | `E(確定)` |
| 実績・下期 | 実績の入力値 | `E(修正)` |

一次の保存を12か月固定にするか疎な保存へ変えるかは保存設計上の案であり、未入力の利用結果を変更する理由にはしない。

### 8.3 判定順序の擬似コード

以下は合意した計算の説明であり、実装済みAPI名ではない。

```text
resolveCurrentAmount(row, kind, month):
    validate row, kind, month
    if explicit value exists for (row, kind, month):
        return that value                 # 0や同額もここで返す
    if kind is primary:
        return 0
    if kind is confirmed:
        return resolveCurrentAmount(row, primary, month)
    if kind is revised:
        return resolveCurrentAmount(row, confirmed, month)
    if kind is outlook or actual:
        source = confirmed if H(month) else revised
        return resolveCurrentAmount(row, source, month)
```

解決先は同じ科目行・同じ月。別の科目・別の月・別施策の値を補完しない。参照先がない不正な行は、0への補完で隠さず読み込み・保存検証で拒否する。

### 8.4 0・同額・未修正の違い

| 状態 | 元予算が10→15に変わった場合 |
|---|---|
| 未修正 | 有効額も10→15に変わる |
| 明示0 | 0のまま |
| 明示10 | 元予算と最初は同額でも10のまま |
| 明示−5 | −5のまま |

同じ金額を入力したことを、差がないから不要な更新と単純に判定しない。未修正→明示同額は、今後の追従を止める意味のある状態変更である。

**未決定D05：** 明示入力を取り除き、再び未修正へ戻す具体的な操作。Deleteで0にする現在の操作を、無断で未修正へ戻す操作に変更しない。

### 8.5 入力を変えたときの伝播

| 変更 | 追従し得る範囲 | 固定される範囲 |
|---|---|---|
| 一次を変更 | 未修正の確定、その先の未修正の修正・見通し・実績 | 途中に明示入力がある枝 |
| 確定を変更 | 未修正の修正、上期の未修正見通し・実績、修正経由の下期 | 明示入力済みの月 |
| 修正を変更 | 下期の未修正見通し・実績 | 上期、明示入力済みの下期 |
| 見通しを変更 | 見通しの入力と関連する表示・集計 | 実績・確定・修正の入力値 |
| 実績を変更 | 実績と、修正の上期実績を参照する表示 | 見通しや予算の入力値 |
| 前年額を変更 | その前年を参照する合計額 | 施策増減の保存値そのもの |
| 計算用前年の選択を変更 | 対象の種別の合計額 | 施策の明示入力・未修正状態 |

見通し・実績・修正の入力で、上流の確定・一次を書き換えない。

### 8.6 前年施策への適用範囲

前年施策は前年度の金額そのものを見通し・実績へ入力するため、当年度の確定・修正を参照しない。非表示の一次・確定・修正に正規の金額が存在し得るか、拒否するか、役割変更時にどう扱うかはD08。

前年の見通し→前年の実績という自動追従は合意していない。独立した値を持つ合意を維持する。片側の未入力をもう片側の金額で埋める設計を追加しない。

## 9. 前年額、合計、比較の計算

### 9.1 集計対象を分ける

同じ科目a、月m、分類条件Fについて、次を区別する。

- `P(v,a,m,F)`：条件に一致する前年施策の、見通し／実績vの合計。
- `S(k,a,m,F)`：条件に一致する当年度施策の、有効な種別kの増減合計。
- `B(k)`：種別kの計算に使う前年の見通し／実績の選択。
- `T(k,a,m,F)`：当年度の合計額。

基本式は次のとおり。

```text
T(k,a,m,F) = P(B(k),a,m,F) + S(k,a,m,F)
```

修正予算の上期実績の表示は10章で別に扱う。ここで、前年施策の金額をSへ含めない。Pに入れた金額を二重加算しない。

### 9.2 前年選択と施策金額は別

- 引き継ぐのは当年度施策の月別増減額。
- 見通し・実績が確定・修正の施策金額を使っても、計算用前年の選択まで自動変更しない。
- 元の予算と同じ合計になることを、引き継ぎだけで保証しない。
- 前年見通しと前年実績が違えば、同じSでもTが違う。
- 見通し・実績のBの選び方・初期値・保存先はD02。予算へ自動同期する案は採用しない。
- 表示用前年 `P表示` とBは別条件として保つ現行規則を、表示共通化だけを理由に統合しない。

### 9.3 金額例

単位は例示上の円整数。

| 前年の選択と金額 | 施策の増減合計 | 合計 |
|---|---:|---:|
| 前年見通し100 | 0 | 100 |
| 前年見通し100 | 10 | 110 |
| 前年実績110 | 10 | 120 |
| 前年実績110 | −5 | 105 |

110と120の違いをエラーや不整合と扱わない。選択した前年額が違うことによる正規の計算結果である。

### 9.4 科目属性と収支

現行の金額項目は次の構成であり、種別拡張だけを理由に変更しない。

| 項目 | 科目属性からの計算 |
|---|---|
| 売上 | 売上属性−売上原価属性 |
| 費用 | 費用属性 |
| 利益 | 売上属性−売上原価属性−費用属性＋利益属性 |

金額項目マスタの共通定義を使い、画面ごとに別の利益計算を作らない。「利益＝売上−費用」とだけ仮定して利益属性の科目を落とさない。属性未設定・科目未選択の入力中行は既存の検証・表示の規則を照合し、保存時には有効な参照と属性を検査する。

### 9.5 期間計と率

- 月別の正確な値から四半期・半期・年間を合算する。
- 年間利益率は年間利益÷年間売上から求め、月別利益率を平均しない。
- 利益率が算出できない条件を0として偽装しない。売上0などの表示は現行規則を維持する。
- 金額差は丸める前の数値の差。利益率差はポイントで表す。
- 表示上の0の空白化は表示処理だけであり、明示0の保存状態を消さない。

### 9.6 精度と上限

現行は千円単位で小数点以下3桁まで入力し、保存と加減算は円整数。表示時に整数千円へ丸める。負数は絶対値で四捨五入し、負の0を残さない。

円整数の現行範囲は−9,007,199,254,740,991〜9,007,199,254,740,991円。途中の相殺を失わないよう集計し、完成した値の範囲を検査する。表示用に丸めた値を次の計算や保存へ戻さない。種別が増えても浮動小数の千円で連鎖計算しない。

## 10. 修正予算の上期実績と循環参照の防止

### 10.1 合意されている年間表示

修正予算の年間額は、上期の実績額と下期の修正予算額の合計とする。上期実績には前年額がすでに含まれるため、再び前年や施策実績を足さない。

説明上、表示用の修正額を `V修正(m)` とすると次の関係になる。

```text
V修正(m) = T実績(m)                if H(m)
V修正(m) = P(B修正,m) + S修正(m)   otherwise
年間修正額 = sum of V修正(m) for 12 months
```

### 10.2 入力値・有効額・表示値を混同しない

当年度施策の修正入力値M、未修正を解決した修正の施策金額E、前年を足した合計T、上期実績を合わせた表示Vを区別する。これを同じ「修正額」という変数へまとめると、上期に意図しない実績上書きや二重加算が起き得る。

**未決定D03：** 上期の修正タブでも実績額を表示するか、入力値は別に保持して表の集計だけ実績を使うか。合意済みの年間表示を根拠に、上期の修正セルを無断で編集禁止にしない。

### 10.3 循環させない依存関係

見通し・実績の下期が参照するのは、その科目行・月の修正の有効な施策金額E。年間合計や上期実績込みのVを施策金額の代わりに参照しない。

上期の実績の未修正値は確定を参照する。下期の実績の未修正値は修正→確定→一次を参照する。修正の上期表示が実績を参照しても、同じ月の実績が修正の表示を参照する構造を作らなければ循環しない。

### 10.4 期間の境界

基準年度の表示は現行では4月〜翌3月。具体例として上期4〜9月、下期10〜3月を使えるが、境界を固定するか変更可能にするかはD04。システムの現在日付だけで参照先を勝手に切り替えない。月mがどの期に属するかと、今が上期か下期かは別の情報である。

## 11. 入力画面と操作

本章は維持すべき操作と設計条件。座標・文言・色・配置・新しい操作の完成案はD05・D08・D11に応じて具体化する。

### 11.1 施策入力・詳細

- 名称・備考・展開・展開区分・部署・業種・期間・科目行を同じ作業面で扱う流れを維持する。
- 前年を入力するために、別の予算名登録や月別明細の一件ずつの登録を前提にしない。
- 展開「前年」を選ぶと見通し・実績だけのタブになる。
- 当年度の施策では5種別を扱う。
- 役割・種別・月に対応した有効金額を表示する。明示値を入力すれば通常の保存へ進む。
- 未修正を単なる空白に見せるか、有効額をどう示すかはD05。現行では引き継ぎを文字色や常設文言で強調していないことも踏まえる。
- 種別を切り替えても未保存の入力・不正入力・行識別子を取り違えない。
- 登録前の下書きと保存済み施策の状態を区別する。

### 11.2 表の編集操作

現行の次の操作を新種別・前年施策でも照合する。

| 操作 | 維持すべき結果 |
|---|---|
| 数字入力・F2・ダブルクリック | 選んだセルの文字編集に入る |
| Enter・Tab・フォーカス移動 | 通常のセル確定・移動。候補採用機能は追加しない |
| Esc | 入力開始前の金額と未修正／明示状態へ戻す |
| コピー | 元の精度の値をコピー。見た目の丸め値で入力を壊さない |
| 貼り付け | 全範囲の科目・月・金額を検証し、部分更新しない |
| 同値入力 | 範囲へ明示入力し、未修正との意味の違いを保持する |
| Delete・Backspace | 現行では0への消去。未修正へ戻す操作に無断転用しない |
| 切り取り | 元の値を保持して移動し、重複範囲でも失わない。失敗時は元範囲を保つ |
| 並べ替え・行移動 | 行識別子と全種別の月額・状態を一緒に移動する |
| 数式入力 | 現行の数値四則演算を計算結果へ確定。式自体は保存しない |

役割別の非表示タブや参照専用の過去閲覧で、貼り付け・ショートカット・内部命令から禁止領域へ書けないよう検証する。

数式の現行範囲は `=` で始まる数値の四則演算と括弧、512文字・括弧32段まで。セル参照・関数は対象外。ゼロ除算、不正式、1円未満の結果、金額範囲超過は確定せず、式と理由を保持する。新種別のために式の実行範囲を広げない。

### 11.3 科目行と合計行

- 科目未選択の行は、金額の保存検証と一体で扱う。
- 一つの施策に同じ科目が複数行あっても、入力行は独立して保存する。
- 売上・費用・利益の参照専用合計は選択中種別の有効額から計算する。
- 前年施策の合計は前年額そのもの、当年度施策の合計は増減額であり、同じ合計部品でも値の意味を取り違えない。
- 不正入力や範囲超過で合計を作れない場合、元の入力を失わない。

### 11.4 アクセシビリティと狭い画面

種別数が増えても、タブの名前・選択状態・操作対象を読み上げとキーボードで確認できるようにする。非表示タブへフォーカスが残る動作を避け、役割変更後のフォーカス先を設計する。

現行の入力幅、表内スクロール、固定見出し、狭い画面での全入力欄への到達を維持する。説明文を常設して表の作業領域を圧迫する方法だけで違いを説明しない。色だけで未修正・明示入力の意味を伝えない。

## 12. 各表、比較、検索、ダッシュボード

### 12.1 施策一覧

現行は1種別を選び、各施策の月別売上・費用・利益を表示する。次期は新種別を同じ有効額から計算する。見通し・実績などを一覧の候補へどう含めるか、初期選択・詳細へ渡す種別はD01・D11。

前年施策を当年度施策と同じ一覧へ出すか、絞り込み・区分で示すかはD06。単に前年施策を通常の増減へ混ぜて一覧の合計を二重加算しない。

### 12.2 総原価表

現行は科目・集計・利益率を縦に並べ、表示する前年と予算の計算用前年を独立して選ぶ。前年列は専用の選択から決まり、予算の選択変更で勝手に切り替えない。見出しは一行で、計算基準の注記を増やさない現行要件を維持する。

現行の差額規則は「表示中で最も後の種別−各先行表示対象」。一次だけなら一次−前年、確定だけなら確定−前年、両方なら確定−前年と確定−一次を表示する。

5種別へ拡張した場合の「最も後」の順序と、表示対象に含める種別はD01。種別の数値IDやクリック順を根拠に無断で差額の符号を決めない。

部署・業種の表示条件と科目集計の構成を守る。前年を一つの分類へまとめた入力では、その分類条件に応じた結果になる。異なる粒度の内訳を、自動で配分して一致させない。

### 12.3 展開表

現行は売上・利益を表示し、前年は既存の上部行で示す。前年列を追加しない。確定と一次の2種別では確定−一次の比較列を持つ。

展開「前年」が施策として存在するようになるため、上部の前年行と前年の施策をどこへ配置するかを決める必要がある。集計上Pへ一度含めることと、詳細行として見せることを分ける。前年行・前年展開計・当年度展開計をすべて足して二重計上しない。

期間・展開区分・施策のまとまり、小計、固定列、部分描画、絞り込み後の再構成を維持する。総原価表と同じ共通計算を使っても、列構成まで同じにしない。

### 12.4 内訳

総原価表の金額から内訳を開く場合、何の金額を見ているかを維持する。前年額なら前年施策、当年度の増減なら当年度施策、合計ならPとSの関係を追える構成が必要。差額の内訳では比較する2条件を保持する。

施策を開いた後に元の表の条件・並び順・スクロール・フォーカスへ戻る既存の流れを維持する。具体的な内訳の列・見出しはD06。

### 12.5 比較対象と差額

| 論点 | 状態 |
|---|---|
| 1種類だけ表示 | 合意済み |
| 最大2種類を比較 | 合意済み |
| 一次・確定・修正を比較候補にする | 合意済み |
| 見通し・実績も比較候補に加える | D01・質問44未回答 |
| 3種類以上を同時表示 | 今回は行わない |
| 比較の順序・符号・初期選択 | D01 |
| 前年表示の選択 | 施策金額の引き継ぎとは別 |

### 12.6 検索と詳細への移動

現行の施策名・備考・分類名による検索を維持し、前年施策も保存された施策として扱う。検索対象へ勝手な補助語を加えない。検索結果からどの種別を開くかは、前年施策に存在しない一次タブを開かないよう役割と種別を照合する。

一覧・展開表・内訳からの種別引き継ぎも同様。先頭の種別を固定で一次へ読み替える旧分岐を、新種別で取り違えない。

### 12.7 複製

施策複製では名称・備考・分類・共通科目行・5種別の直接入力と未修正状態を独立して複製できる必要がある。コピー先の科目行と施策の識別子は新しくする。複製しただけで合計へ加算せず、登録したときに保存する現行の流れを維持する。

前年施策の複製は前年度の金額を持つ施策の複製となる。年度引き継ぎとは別操作。表示上の有効額だけをコピーすると未修正が明示値へ変わるため、どの状態を複製するかを保持する。

### 12.8 開始年月と期間

現行は新規／期間差の規則と、種別別の有効月額から開始年月を導出する。正負の相殺前に活動月を検出し、保存値として持たない。

新種別の開始年月にも同じ仕組みを拡張するか、前年施策には開始年月を表示しないかはD11。前年度の月を当年度の暦年で表示して一年ずらさない。表示項目を増やすこと自体を目的にしない。

### 12.9 ダッシュボード

現行の年間指標、月別推移、部署・業種・展開・期間・科目別の図は前年と施策増減を共有している。次期は前年を施策から集計し、新種別の有効額を共通処理から受け取る。

特に、前年施策を「施策の影響」「展開別増減」へ混ぜると、前年額そのものが当年度の施策効果として順位や構成を占めてしまう。前年額と当年度増減を明示的に分ける。分類別の図のP＋Sと、展開・期間別のSだけという意味の違いを守る。

新種別の選択、指標・差・図の比較、総原価表や施策詳細への移動条件をD01・D11で決める。図ごとに異なる前年・種別で計算しない。

## 13. 保存構造、読み込み、更新、同期

### 13.1 現行の保存単位

| 現行テーブル | 現行の内容 | 次期の検討 |
|---|---|---|
| `document_info` | 年度と日時 | ファイル単位の情報を維持 |
| `initiatives` | 共通属性・分類・名称・identity | 前年役割を持つ施策も共通に扱う |
| `initiative_rows` | 科目行と永続する文字列ID・順序 | 種別と金額を増やしても行を複製しない |
| `initiative_amounts` | 種別・月・円整数・更新番号 | 5種別と明示入力を保存できる制約へ変更 |
| `previous_amounts` | 前年見込・前年実績の別保存 | 正本としては置き換える方針。次期で不要な二重正本を残さない |
| `kind_selections` | 表ごとの種別と前年条件 | 種別拡張と独立した前年条件を表現する |
| `expansions` | 展開の名称・コード | 「前年」の役割と識別の保存を検討 |
| 各マスタ・所属 | 科目属性・分類・集計・所属 | 参照保護を維持 |

### 13.2 保存設計案

具体的なDDL・数値ID・形式番号は未確定。以下は実装案として整理する。

1. 展開に通常／前年の役割を保存する。
2. 当年度の一次と前年施策の2種別を直接値として扱い、下流種別は明示月だけ保存する。
3. 有効額や各表の合計は計算し、重複した保存金額にしない。
4. `previous_amounts` を新しい施策保存の横へ正本として温存しない。
5. 種別ごとの前年条件を、一次・確定専用の固定分岐から拡張する。
6. 更新番号の対象を、科目行・種別・月と役割・共通属性に対応させる。

別の汎用ルールエンジンやユーザー定義の参照グラフを導入する合意はない。5種別の決まった関係を、共通の型と処理で明示する程度を基本案とする。

### 13.3 読み込み検証

- 対応する保存形式と必須テーブル・列・制約を確認する。
- 未知の種別、未知の役割、存在しない科目行・分類への参照を拒否する。
- 月は1〜12、金額は円整数、年度はファイルの有効範囲で検査する。
- 役割に対応しない種別の値をどう扱うかD08で決める。勝手に読み飛ばしてデータがないことにしない。
- 明示0・同額の値を未修正へ変換しない。
- 同じ識別子の重複、孤児の金額、再利用された分類・施策の同一性の取り違えを拒否する。
- 不正ファイルを開いた失敗で、元ファイルを書き換えない。
- 保存データから種別別の開始年月を導出する処理も、5種別と役割を検証してから行う。

### 13.4 保存の確定境界

現行は元のバイト列から編集用コピーを開き、変更と取消・履歴を準備し、実ファイルへの書き込み成功後だけ保存済み状態を置き換える。次期もこの境界を維持する。

保存の手順は、入力検証→参照と更新番号の照合→コピー上で変更→業務データ全体の検証→取消・履歴の準備→実ファイルの外部変更確認→書き込み→現在状態の公開、と整理する。読み込みのたびに勝手な移行や補完をしない。

保存失敗・許可拒否・キャンセルでは、入力と最後に保存できた状態を保持する。下流の有効額だけが先に保存済みとして公開される状態を作らない。

### 13.5 複数ウィンドウと外部変更

同じ施策の別月、別種別、共通属性の変更を区別する。新種別を追加したために、別種別の独立編集まで常に競合させたり、同じ種別・月の相反変更を上書きしたりしない。

特に未修正と同額の明示入力は、値が同じでも状態が違う。元の予算を変更する保存と、下流を明示同額へ固定する保存が交差した場合、どの時点の何を利用者が入力したかを更新基準と合わせて確認する。

役割変更・科目削除・分類変更は複数種別へ影響する。独立と判断できる範囲だけ統合し、安全に統合できない変更は元ファイルへ上書きしない。現行の別ファイルへの保存による回復経路を維持する。

### 13.6 派生計算とキャッシュ

キャッシュの入力条件には、役割、種別、月、明示入力、参照する予算、計算用前年、分類・科目属性・表示条件を必要に応じて含める。予算を変更したのに未修正の見通し・実績が古い値のままになる構造を避ける。

保存・スクロール・フォーカスなど金額に無関係な変化で全件計算を繰り返さず、元データの変更に応じて再計算する現行の方針を維持する。

## 14. 年度の引き継ぎ

### 14.1 合意と未決定

前年度の施策実績を翌年度の前年へ引き継ぐ方針は合意済み。引き継ぎ元・先のファイル、入力の選択、施策の粒度、見通しをどう使うかは未決定D07。旧保存形式の移行とは別の業務機能である。

### 14.2 金額の成立条件

年度Yの実績合計を `T実績_Y`、年度Y+1の前年実績合計を `P実績_Y+1` とすると、同じ分類・科目・対応月で次が成立する必要がある。

```text
P実績_Y+1 = T実績_Y = P(B実績_Y) + S実績_Y
```

S実績だけをコピーすると前年度の前年額が欠落する。例えば前年100＋当年度施策実績10＝実績110なら、翌年度の前年は110であり10ではない。

### 14.3 内訳の持ち方の案

| 案 | 起こること | 利点・制限 |
|---|---|---|
| 分類・科目ごとに合算して前年施策を作る | P＋Sを業種・部署・科目・月単位でまとめる | 施策数を抑えやすいが、元施策ごとの内訳は前年施策にそのまま残らない |
| 元の構成を保って前年施策を作る | 前年額を持つ成分と当年度増減の成分を、合計が一致する形で引き継ぐ | 内訳を残せるが、施策名・分類・役割・科目行の対応と件数の増加を設計する必要がある |

どちらも案であり、利用者の「必要なら細かく、面倒ならまとめる」という方針に沿って決める。元施策の増減を、前年度の施策別売上そのものと勝手に読み替えない。

### 14.4 元データ・識別・分類

- 引き継ぎ元は書き換えない。
- コピー先の施策・科目行は新しい所有情報と識別子を持つ案を基本とし、出典の追跡が必要かは別途決める。
- 名称の衝突、削除された科目、分類の変更、所属違い、年度の有効範囲を検査する。
- 1〜3月の暦年表示と、前年としての対応月をずらさない。
- 前年の見通し・実績のどちらへ何を入れるかを決める。実績が未修正で予算額を使う月があることを、引き継ぎの確定済み判定へ読み替えない。
- 処理途中のキャンセル・保存失敗で元データや既存の先ファイルを失わない。

### 14.5 当年度の通常施策の初期化

翌年度に前年額を作ることと、翌年度の通常施策を再利用することは別。通常施策も複製するか、名称・分類だけ残して新年度の金額をどう始めるかは未決定。前年度実績の増減を新年度の増減へそのまま足して二重効果を作らない。

## 15. 操作取消、時点履歴、過去閲覧

### 15.1 操作取消・やり直し

現行要件の操作取消は100操作を上限とする。種別拡張だけを理由に上限を変更しない。値だけでなく、未修正／明示入力、役割、種別、前年の選択を戻す。未修正へ戻した後は、その時点の正しい上流値を参照する。取り消したセルへ過去の有効額を明示値として戻して追従を止めない。

同額の明示入力も状態変更として取消可能にする。科目行や施策の作成識別子を用い、削除・再作成された別の対象に操作を適用しない。

### 15.2 時点履歴の記録

現行は同じ `.triadic` に履歴を持ち、初回変更前と、未記録の変更開始から5分を目安に保存状態を記録する。保存のたびに期限を延ばさず、正常なファイル終了・過去閲覧への切り替えでは未記録分を記録する。現在のコードでは業務スナップショットと履歴管理を分け、過去履歴を各記録へ入れ子にしない。

次期のスナップショットにも前年施策・5種別・明示入力・前年条件を含める。合計や引き継いだ有効額を重複保存しない。新しい表・役割属性を業務テーブル一覧から漏らすと、通常保存では見えるが履歴復元では消えるため、定義・転記・検証を同時に更新する。

### 15.3 過去閲覧

履歴の金額、役割、マスタ、前年条件だけから同じ結果を再計算する。現在の確定・修正・前年額を履歴の未修正セルへ混ぜない。

種別や表示条件の閲覧内切り替えは許可し、過去データを保存・編集しない。前年タブの制御・検索・詳細・ダッシュボードにも共通の参照専用状態を渡す。

### 15.4 履歴比較

変更項目の比較は、役割、分類、科目行、明示金額、未修正／明示、前年条件を区別する。新しく増えた有効額の変化を、すべて独立入力の変更として列挙しない。

収支への影響は、各時点の前年施策と種別有効額から計算する。前年の定義変更、確定変更による下流への伝播、明示0の固定を区別して追える必要がある。比較対象・前年条件・修正の上期実績表示をどのように選ぶかはD01・D03・D11。

### 15.5 復元・削除・失敗

現在の履歴管理を維持しつつ、選んだ業務データ全体を戻す。復元前後の記録を残し、失敗時は現在と閲覧中の過去を保持する現行の境界を維持する。新種別だけ復元対象外にしない。

履歴削除は現在の金額を変えず、識別子を再利用しない。履歴を削除して初回記録状態へ戻さない。タブ終了・強制終了時の非同期保存完了を新しく保証したと説明しない。

## 16. Excel入出力

### 16.1 現行の整理

現行は総原価表・展開表・施策一覧と「計算元」を出力し、前年入力フォーマットだけが専用の取り込み対象となる。計算元には前年と施策金額を持ち、数式で表示表を再計算する。出力は開いているファイルを自動更新しない。

### 16.2 次期で必要な変更

- 前年額の出力元を展開「前年」の施策へ対応させる。
- 5種別、役割、参照する前年、修正の上期実績表示を画面と同じ定義で出す。
- 元の入力値と有効額のどちらを出力するかを明確にする。
- 合計は前年と当年度増減を二重加算しない。
- 新種別の値・差額・期間計・利益率の式を更新する。
- 画面で絞り込んだ表示と、出力対象の全件の扱いを既存規則と合わせる。
- 予算額を参照するだけのセルが、Excel出力によって明示入力へ変換されたと誤解されないよう、出力の目的と制約を決める。

### 16.3 出力モデルの未決定D12

| 案 | 内容 | 違い |
|---|---|---|
| 有効額を出力 | 出力時点の解決済み金額を各種別に入れる | 単純に再計算できるが、Excel内の上流変更へ追従する意味は別途表現が必要 |
| 入力と参照を出力 | 明示値と未修正の参照を区別して式を生成する | 予算変更の追従を再現しやすいが、構成・式・取り込みの判定が増える |

現行Excelでは一次・確定を独立した金額として編集する部分がある。次期でアプリと同じ参照関係を保証するかは、既存の出力動作を確認して決める。アプリの合計が出ることと、Excelで編集した後の参照関係まで同じであることを区別する。

### 16.4 前年入力フォーマット

前年専用画面を施策入力へ統合するため、既存の前年フォーマットをそのまま残すとは決めていない。廃止するか、前年施策の入力フォーマットとして作り直すか、施策全般の取り込みへ拡張するかはD12。

一般的な決算資料から部署・業種を推測して自動配分する機能や、公式数値の「答え」を取り込む機能は今回の対象ではない。

### 16.5 取り込みを維持する場合の条件

取り込みを採用した場合だけ、年度、施策・科目行・分類の同一性、役割、種別、月、明示0・空欄・未修正を識別する。変更確認と一回の保存、競合拒否、元ファイル保護を維持する。数値が同じでも未修正と明示入力の意味を失わない。

現行の取り込み制限は圧縮20MiB、ZIP項目2,048、1項目の展開8MiB、展開全体32MiB、行100,000、列20、セル200,000、XMLタグ1,000,000、解析30秒。これらは現行の前年フォーマットの境界であり、新形式の設計で再評価する場合も根拠を示す。ZIP・XML・セル数・処理時間の既存の入力境界を削除しない。専用Workerで解析し、保存用Workerと分ける。出力・取り込み関連の検証は通常検証とは別に実行する。

## 17. 性能、処理の分離、エラー対応

### 17.1 計算の規模

5種別へ増えても、共通の施策・科目行・分類を種別ごとに5倍複製しない。金額の解決は最大で見通し／実績→修正→確定→一次という固定された長さの参照である。任意の循環グラフ探索を持ち込まない。

前年施策は一度分類・科目・月・見通し／実績で索引化し、同じ条件の計算で使い回す案を基本とする。ソースが変わったときだけ再構築する。

### 17.2 UIとWorker

計算・保存・Excelの既存のWorker境界を維持する。Chrome APIや実ファイルの読み書きは拡張環境の入口に置き、共通の金額・集計はcoreへ置く。UI部品ごとに独自の種別解決を作らない。

大量の施策や科目行でも、既存の部分描画と全件計算・並べ替えの整合を保つ。画面に出ていない中間行を合計やコピーから落とさない。

### 17.3 エラーの扱い

| 条件 | 維持するもの | 必要な動作 |
|---|---|---|
| 不正金額・不正式 | 入力文字列と保存済みデータ | 理由を示し、正しい値へ確定しない |
| 保存許可拒否・キャンセル | 入力と元ファイル | 再試行・取消の既存操作を保つ |
| 外部更新との相反 | 今回の入力と相手の保存内容 | 独断で上書きせず回復経路へ進む |
| 読み込み不正 | 現在のファイルと選択前の状態 | 理由を示し、移行・補完しない |
| 集計範囲超過 | 元の科目行・入力・正常な対象 | 正常な行まで編集不能にせず、計算不能を区別する |
| 役割と種別の矛盾 | 元の保存値 | 黙って捨てず、検証・明示的な変換方針に従う |
| 年度引き継ぎ失敗 | 元年度のファイル | 中途半端な先ファイルを成功として扱わない |

失敗のたびに新しい再確認や入力画面を足す方針ではなく、既存の保存境界と回復操作を利用する。

## 18. 安全性、権限、互換性、配布

- 利用者データは `.triadic` のローカルファイルで扱い、今回の機能のために外部送信やクラウド認証を追加しない。
- リモートコードや拡張ページの外部スクリプトを導入しない。
- 文字列をHTMLとして実行しない。分類名・施策名・備考も同じ扱いにする。
- 新種別・前年の役割・保存構造の変更に合わせてファイル形式の番号を決める。未確定段階で新番号を先取りしない。
- 過去形式を読み替えて動かす互換経路は、明示許可のない限り追加しない。対応しない形式は理由を示して拒否し、元ファイルを書き換えない。
- 通常の開発では版番号を勝手に上げない。リリース準備は別の明示された範囲で行う。
- 編集元はTypeScript／ReactのソースとManifest template。配布JavaScript・CSS・Manifestを手編集しない。
- buildで両配布物とZIPを更新し、成果物が変わる実装と同じコミットへ管理対象生成物を含める。ZIPと `.triadic` はコミットしない。
- AGPLv3と既存依存のライセンスを維持する。依存追加は必要性とライセンスを確認する。

## 23. サンプルと業務上の確認例

- 修正予算と当初確定予算の比較、年間の着地見込み。
- 年度引き継ぎの金額成立と、元データを保護する失敗例。
- 取消・履歴・復元・Excel・関連する各表の照合。

現在のサンプルを未実装仕様へ先に書き換えない。実装に合わせて業務設計→生成元→テスト→対応表→実ファイルの順で更新する。

エージェントが作成するサンプルは、部署以外のマスタをその時点の製品デフォルトと一致させる。製品で合意して追加する「前年」と5種別を使うことと、サンプルの都合で製品のデフォルトを変更することを区別する。

生成した `.triadic` はGit対象外。ソースと確認手順だけを管理し、配布ZIPへサンプルを含めない。

### 24.2 全体の完成条件

1. 対象範囲のDが決まり、保留するものは製品上の制限と影響を明示する。
2. 前年を施策で用意し、5種別を入力・保存・再読込でき、D01で確定した対象を表示・比較できる。
3. 未修正と明示入力、前年の選択と金額の引き継ぎを混同しない。
4. 修正の上期実績表示と当年度施策の参照が循環せず、二重加算がない。
5. 入力から各表・ダッシュボード・履歴・Excelまで同じ元データと計算を使う。
6. 年度引き継ぎで前年合計が成立し、元ファイルを保護する。
7. 保存失敗・競合・取消・履歴復元で金額・状態・識別を失わない。
8. 文書・対応図・サンプル・生成物・検証結果が実装と一致する。
9. 対象外の自動照合や残差、未合意の互換処理を再導入していない。
10. 未実施・未確認を成功と扱わず、実装・検証・設計の完了を区別して報告する。

## 26. 今後の文書更新の単位

本書を次期アップデートの設計の入口として継続更新する。新しい判断が決まったら、用語・合意一覧・計算・画面・保存・影響箇所・決定表・受入条件のうち関係する箇所を同時に更新する。

名称だけを直して計算が旧名のまま残る、候補方式を撤回したのに検証ケースへ残る、対象外の残差に依存した未決定事項を維持する、といった状態を避ける。作業履歴は本文へ蓄積せず、コミット本文に記録する。

大規模であっても、未決定を解消したように見せるために仕様を追加しない。必要な働きとデータ保護に関係するところまで具体化し、実装方法の選択肢と理由を残す。

## 27. 用語と金額の取り違えの最終確認

- 「前年」は展開であり、当年度の種別を一つ増やす話ではない。
- 前年施策の見通し・実績は前年度の金額そのもの。
- 当年度施策の見通し・実績は前年からの増減額。
- 確定や修正から引き継ぐのは施策金額であり、前年の選択ではない。
- 未修正は0ではなく参照状態。明示0は正規の固定入力。
- 見通しは修正予算のためだけの値ではない。
- 実績という種別名だけで、全月の明示入力や決算確定を保証しない。
- 修正の入力・有効額と、上期実績を含む年間表示は分ける。
- 翌年度の前年は前年度のP＋S。Sだけではない。
- 「答え」・自動照合・残差を今回の設計へ戻さない。
