# 業務計画サンプルと確認手順

[全機能確認用.triadic](全機能確認用.triadic)は、架空の事業会社の2026年度予算として読める業務計画です。136施策・509科目行、デフォルト57科目・15集計・7展開・6展開区分・9業種、東日本営業部・西日本営業部の2部署、前年実額と3時点の履歴を含みます。実在企業のデータは使用していません。確認専用の科目・集計・部署、全月0の準備施策、相殺や操作確認だけを目的とした施策を含めません。過去の履歴にも同じ条件を適用します。

基本の10施策に、全7展開×9業種×2部署の126施策を加えています。施策は車両整備、法人車両、月極賃貸、施設運営、定期配送、構内作業、委託管理、本社支援、保有資産を扱い、契約数量・単価・季節変動・開始時期と確定予算での変更理由を備考へ記載します。金額は千円単位で、小数点以下3桁は1円です。50,000,000bytes以下を生成・一致検査・通常テストで検証します。

新規ファイルのデフォルト自体は変更しません。配布サンプルで部署の名称を業務上の名称に変更します。通常の小規模画面テスト（14施策）は境界値・空欄・削除制約の確認に使用し、配布ファイルへは含めません。実ファイルと同じ内容は画面テスト入口の「業務計画サンプル（136施策）」または `?data=large` で表示します。

## 再生成と検証

`npm run samples:generate`で正式な保存処理を使って生成し、`npm run samples:check`で保存済みファイルと生成元の全テーブル・全値を照合します。`npm run verify`はbuild・型・通常テスト・生成一致・version一致を確認します。`.triadic`はローカルに保持し、Gitには含めません。編集済みサンプルは再生成前に別の場所へコピーしてください。

[tests/reference-sample.mjs](../tests/reference-sample.mjs)で、業務上の名称、確認専用レコードの排除、全分類、非0の施策、金額前提、全月の独立計算、三表・期間計、全履歴、Excel再読込を検査します。[tests/sample-plan.mjs](../tests/sample-plan.mjs)と小規模・専用画面テストで境界条件も検証します。実ファイルを開くだけで、許可拒否や保存失敗などの全操作を実施済みとは扱いません。今回のCodex内ブラウザでは業務計画の読み込み、136件の施策一覧、東日本営業部・西日本営業部の部署表示と所属を確認します。実ファイルへの書き込みと実環境の許可拒否は実施しません。
